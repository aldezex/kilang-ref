# E0701: non-exhaustive match

A `match` is an expression, so it has a value for every value it can be given. If some value reaches no
arm, the program would have nothing to compute for it, and Ki does not leave that to a crash at run time:
the `match` must cover every value of the type it takes apart.

The primary label is on the value being matched, and it shows a witness, a pattern that no arm covers:
``pattern `Rect(_, _)` not covered``. The compiler builds it from the arms (Maranget's algorithm), so it
is a value that you can write as the arm that is missing: a constructor with a `_` for each field, `true`
or `false`, a tuple or a record with the part that is missing and `_` elsewhere. For an `Int` the witness is
the smallest non-negative number that no arm reaching that place names, because no list of literals covers
all the integers: a `match` on an `Int` always needs a `_` or a variable. In a `(Bool, Int)` with the arms
`(true, 0)` and `(false, 1)`, the arm for `true` names 0 and the one for `false` names 1, so the witnesses are
`(false, 0)` and `(true, 1)`. If several kinds of value are missing, the label
lists up to three, ``patterns `Rect(_, _)` and `None` not covered``, and says `and more` when there are
more than three. The number of them is never counted: it depends on how the check splits the values, so
it would not be the same count from one version to the next. A note repeats the rule, and the help says
``add an arm for `Rect(_, _)` ``. There is no edit, because what the arm should do is for you to say.
When a witness that the label shows has a number in it, the help ends with ``, or end the `match` with a `_`
arm``: the arm for `3` only moves the witness to `4`, and the `_` is what ends the list. A number in a witness
that the label does not show, one of those that `and more` stands for, does not add it: the help says what
the reader can see, and the `_` comes when that witness is shown.

A `match` in which the parser found a mistake in one of the arms is not judged, here or for W0701: the
arms that were read may not be the ones the program has (a `)` that is missing lets an arm swallow the
ones after it), so the mistake that the parser reported is the one thing said.

An arm with a guard, `n if n > 0 => …`, does not count towards covering the value: the guard can fail,
so Ki assumes it does. An arm that covers nothing new is a warning of its own (W0701).

## Erroneous example

```ki erroneous
type Shape { Circle(Float), Rect(Float, Float) }
fn area(s: Shape) -> Float {
  match s {
    Circle(r) => 3.14 * r * r
  }
}
fn main() {}
```

`Rect` has no arm. The label says that ``pattern `Rect(_, _)` not covered``.

## Corrected

```ki corrected
type Shape { Circle(Float), Rect(Float, Float) }
fn area(s: Shape) -> Float {
  match s {
    Circle(r) => 3.14 * r * r
    Rect(w, h) => w * h
  }
}
fn main() {}
```

## Erroneous example

```ki erroneous
fn sign(n: Int) -> Int {
  match n {
    0 => 0
    m if m > 0 => 1
    m if m < 0 => 2
  }
}
fn main() {}
```

The two arms with a guard do not count, and the literal `0` is not all of `Int`, so the witness is the
smallest number that no arm names, ``pattern `1` not covered``. Ending the `match` with `m => …` or `_ => …`
covers every number.

## Corrected

```ki corrected
fn sign(n: Int) -> Int {
  match n {
    0 => 0
    m if m > 0 => 1
    _ => 2
  }
}
fn main() {}
```
