# E0302: <name> is defined more than once

Two top-level definitions of the same module have the same name and live in the same name space. A
use of the name stands for the first one, and the second is an error. The compiler points at the second
definition and, as a secondary label, at the first.

There are two name spaces. The functions and the constructors of a `type`, which are used as values,
share one; the types, which only a type annotation names, have the other. Two functions, two types or two
constructors with one name are a repeat, whether the constructors are in the same type or in two. A type
and a constructor called alike (`type Circle { Circle(r: Float) }`) are not: they are in different spaces.

Two fields of one record with the same name are a repeat too: the fields of a record have a name space
of their own, so a field may have the name of a field of another record, or of a function.

Which of the two stays is not for the compiler to say, so it suggests renaming one or deleting the
second and offers no edit.

## Erroneous example

```ki erroneous
fn f() {}
fn f() {}
fn main() { f() }
```

The second `f` is the mistake.

## Corrected

```ki corrected
fn f() {}
fn g() {}
fn main() { f() }
```

## Erroneous example

```ki erroneous
type Shape { Circle(r: Float) }
type Shape { Square(side: Float) }
fn main() {}
```

Two types with the same name, whatever form each has. The second `Shape` is the mistake, and its
constructor `Square` is still defined. The name `Shape` stands for the first type, so a `Square` is
not a `Shape` where one is written (`let s: Shape = Square(1.0)`): that is an E0401 that reads
``expected `Shape`, found `Shape` ``, and its note says that the program declares a type with that name
more than once. Mending the repeat mends both.

## Corrected

```ki corrected
type Shape { Circle(r: Float) }
type Solid { Square(side: Float) }
fn main() {}
```

## Erroneous example

```ki erroneous
type Shape { Circle(r: Float), Square(side: Float) }
type Other { Circle }
fn main() {}
```

A constructor is a name among the values, so two types cannot have one of the same name: the `Circle` of
`Other` is the mistake, and the secondary label shows the `Circle` of `Shape`. The same goes for two
variants of one type.

## Corrected

```ki corrected
type Shape { Circle(r: Float), Square(side: Float) }
type Other { Dot }
fn main() {}
```

## Erroneous example

```ki erroneous
type Point { x: Float, x: Int }
fn main() {}
```

The second `x` is the mistake, and the secondary label shows the first. The record keeps the first `x`
as its field, so a literal that gives `x` once is not missing anything.

## Corrected

```ki corrected
type Point { x: Float, y: Int }
fn main() {}
```
