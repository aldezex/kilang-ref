# E0405: cannot construct an infinite type

When a type is not written, the compiler gives it a name of its own, `a`, and finds out what it is
from the way the program uses it. If the only way to make a use work is for `a` to be a type that
contains `a`, there is no such type: `a` would have to be `(a) -> ()`, and inside that `a` would have
to be `(a) -> ()` again, and so on without end. This check is called the occurs check.

The primary label is on the expression whose type would contain itself. The note writes the type
variable and the type it would have to be, with the same names in both. The compiler offers no help
and no edit, because it cannot tell which of the two uses is the mistake.

`ki check` does not run the type checker yet, so for now it reports none of this. The fence that says
`pending=T36` is the sign of that: when the type checker is wired in, that word and this paragraph
go away.

## Erroneous example

```ki erroneous pending=T36
fn f(x) { f(f) }
fn main() { }
```

The parameter `x` has no annotation, so its type is a variable `a`, and `f` has the type `(a) -> ()`.
The call `f(f)` passes `f` where a value of type `a` is expected, so `a` would have to be
`(a) -> ()`. The label on the argument says `this type would contain itself`, and the note says
that `` `a` would have to be `(a) -> ()`, which has no finite size ``.

## Corrected

```ki corrected
fn f(x: Int) { if x > 0 { f(x - 1) } }
fn main() { f(3) }
```

Writing the type of the parameter says what it is, and the call passes a number.
