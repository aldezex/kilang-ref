# E0412: not a record

A field is read with `.x`, or a record literal `Name { … }` is written, and what is meant is not a
record. Only a record has fields. A type with variants (`type Shape { Circle(r: Float), … }`) is taken
apart with `match`, and a builtin type such as `Int` has nothing to read.

The primary label is on the name after the dot, or on the name of the literal, and says `has no fields
to access`. When the type is declared in the same file a secondary label points at it, `` `Shape` is
defined here``. When it is a type with variants the note says `only a record has fields; a sum type is
taken apart with `match``. There is no help. An alias of a record is the record, so its name can be used
in a literal.

## Erroneous example

```ki erroneous
type Shape { Circle(r: Float), Square(side: Float) }
fn main() {
  let s = Circle(1.0)
  printFloat(s.r)
}
```

`s` is a `Shape`, and a `Shape` is a `Circle` or a `Square`: it has no field `r` until a `match` says which
variant it is. The label is on the `r`.

## Corrected

```ki corrected
type Circle { r: Float }
fn main() {
  let s = Circle { r: 1.0 }
  printFloat(s.r)
}
```

## Erroneous example

```ki erroneous
fn main() { let n = Int { x: 1 } }
```

A builtin type is not a record either, so a literal that names it is this error, with the label on the
`Int` and nothing else.

## Corrected

```ki corrected
type Wrapper { x: Int }
fn main() { let n = Wrapper { x: 1 } }
```
