# E0707: this `match` is too complex to check

To know that a `match` covers every value, the compiler works through the arms and the values they leave
open. For most programs that is a few steps. For some it is not: finding a value that no arm matches is
NP-complete, because a `match` on a tuple of `Bool` can encode the satisfiability of a boolean formula (each
arm is the set of assignments that make one clause false, so the arms cover every assignment exactly when the
formula has no solution, and a value that they leave out is a solution). No algorithm answers all such matches
quickly, and a compiler that tried to would hang on them.
So the check has a budget of 10 000 000 steps, and when a `match` needs more, that is an error: the compiler
does not say that it covers every value, and does not say that it does not.

A step is a piece of the search: a case that it explores, a row of the arms that it builds for one, a
part of a pattern that it moves. The primary label is on the value being matched, ``checking it needs more
than 10 000 000 steps``. A note says why, and the help gives two ways out. A `match` that ends with an arm that
matches everything, `_` or a variable, covers every value with no search at all, so that arm always works.
Matches that are split into nested ones, each on a few values, are small again.

What the compiler does with the arms that nothing reaches (W0701) is a favour and not a promise: it looks
for them with what is left of the budget, and a `match` that is too long to compare arm by arm is not an
error, only a match that has no such warnings from the arm where the search stopped. A `let` with a pattern
that is too complex has the same error, worded for the `let`, and so are its note and its help: a `let` has no
arms to end with a `_`, so it says to write `_` where every value matches, or to take the value apart with
`match`es of a few values each.

## Erroneous example

```ki erroneous
fn f(a: Bool, b: Bool, c: Bool, d: Bool, e: Bool, f: Bool, g: Bool, h: Bool, i: Bool, j: Bool, k: Bool, l: Bool, m: Bool, n: Bool, o: Bool, p: Bool, q: Bool, r: Bool, s: Bool, t: Bool, u: Bool, v: Bool, w: Bool, x: Bool) -> Int {
  match (a, b, c, d, e, f, g, h, i, j, k, l, m, n, o, p, q, r, s, t, u, v, w, x) {
    (true | false, true | false, true | false, true | false, true | false, true | false, true | false, true | false, true | false, true | false, true | false, true | false, true | false, true | false, true | false, true | false, true | false, true | false, true | false, true | false, true | false, true | false, true | false, true | false) => 1
  }
}
fn main() {}
```

Each `true | false` is two cases, and the compiler has to try them one after another in every column:
twenty-four of them are sixteen million cases. The pattern says what `_` says, but the search cannot know it
without trying.

## Corrected

```ki corrected
fn f(a: Bool, b: Bool, c: Bool, d: Bool, e: Bool, f: Bool, g: Bool, h: Bool, i: Bool, j: Bool, k: Bool, l: Bool, m: Bool, n: Bool, o: Bool, p: Bool, q: Bool, r: Bool, s: Bool, t: Bool, u: Bool, v: Bool, w: Bool, x: Bool) -> Int {
  match (a, b, c, d, e, f, g, h, i, j, k, l, m, n, o, p, q, r, s, t, u, v, w, x) {
    _ => 1
  }
}
fn main() {}
```
