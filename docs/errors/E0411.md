# E0411: field given twice

A record literal, or a record pattern, names each field once. When the same name appears a second time there are two values
for one field, and the program does not say which one counts.

The primary label is on the second name, `given again here`, and a secondary label on the first, `first
given here`. The help says `remove one of them`, and when the second field and its comma are on one line
the compiler offers the edit that deletes them, with its indentation if it is alone on its line. That
leaves an empty line: an edit works inside one line and cannot take the line break. Which of the two
values is the right one is for the program's author to say, so the edit removes the second, and the first
is the one that stays. Each of the two values is still checked against the type of the field.

## Erroneous example

```ki erroneous
type Point { x: Float, y: Float }
fn main() { let p = Point { x: 1.0, x: 2.0, y: 3.0 } }
```

`x` is given at the start and again after it. The edit deletes `x: 2.0, `.

## Corrected

```ki corrected
type Point { x: Float, y: Float }
fn main() { let p = Point { x: 1.0, y: 3.0 } }
```

## Erroneous example

```ki erroneous
type Point { x: Int, y: Int }
fn first(p: Point) -> Int {
  match p {
    Point { x: a, x: b, y } => a
  }
}
fn main() {}
```

In a pattern the second `x` is just as much a second pattern for one field. The labels are the literal's,
and there is no edit: a pattern does not know where its commas are. Two puns of one name, `Point { x, x }`,
are the one E0704, which says the variable is bound twice, and not this error as well.

## Corrected

```ki corrected
type Point { x: Int, y: Int }
fn first(p: Point) -> Int {
  match p {
    Point { x: a, y } => a
  }
}
fn main() {}
```
