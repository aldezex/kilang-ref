# E0101: invalid UTF-8 byte

A Ki source file must be valid UTF-8, the encoding that nearly every editor uses by default.
The compiler found a byte that cannot be part of any UTF-8 character, so it cannot read the file.
It reports only the first such byte: a file that is not text at all has thousands of them, and
one error says everything the rest would.

The usual cause is a file saved in an older encoding, such as Latin-1, where `é` is the single
byte `0xE9`.

## Erroneous example

The block is written as a Go string because a text file of this repository cannot hold the invalid byte itself.

```ki erroneous escaped
"fn main() { print(1) }\n// caf\xE9\n"
```

The comment ends in the byte `0xE9`, which is `é` in Latin-1 and not valid UTF-8. The compiler
points at the byte, says that Ki source files are UTF-8 and suggests saving the file as UTF-8 or
deleting the byte. It offers no edit: deleting one byte of a longer sequence would leave half of a
character, and changing the encoding of a file is not a change to its text.

## Corrected

```ki corrected
fn main() { print(1) } // café
```

The file is saved as UTF-8, where `é` takes the two bytes `0xC3 0xA9`.
