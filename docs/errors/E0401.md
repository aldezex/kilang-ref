# E0401: mismatched types

Every expression has a type, and Ki checks it against the type that its place expects: the annotation
of a `let`, the return type of a function, the parameter of a call, the other branch of an `if`, the
operand of an operator. When the two are different types, this is the error. Ki converts nothing by
itself, so an `Int` is never taken for a `Bool` or the other way round, and there is no edit that the
compiler could propose.

The primary label is on the expression that was found and says ``expected `X`, found `Y` ``. A secondary
label points at the place that made `X` the expected type, and what it says depends on that place; each
example below shows one. Function types are compared part by part, and the label writes the two
types, such as `(Int) -> Bool` and `(Int) -> Int`, whichever part differs. A type that takes more than
256 bytes to write is cut there and ends in `…`.

`ki check` does not run the type checker yet, so for now it reports none of the errors below. The
fences that say `pending=T36` are the sign of that: when the type checker is wired in, those words
and this paragraph go away.

## Erroneous example

```ki erroneous pending=T36
fn main() { let x: Bool = 1 }
```

The annotation says that `x` is a `Bool` and the initializer is an `Int`. The label on the `1` says
``expected `Bool`, found `Int` ``, and the secondary label on the annotation says `expected because of
this annotation`.

## Corrected

```ki corrected
fn main() { let x: Bool = true }
```

## Erroneous example

```ki erroneous pending=T36
fn f() -> Int { true }
fn main() { }
```

The last expression of a body is what the function returns, and it must have the return type. The
label on the `true` says ``expected `Int`, found `Bool` ``, and the secondary label on the return type
says `expected because of the return type`.

## Corrected

```ki corrected
fn f() -> Int { 1 }
fn main() { }
```

## Erroneous example

```ki erroneous pending=T36
fn f() { 1 }
fn main() { f() }
```

A function with no `->` returns `()`, so its last expression has to be `()`. Here it is an `Int`, and
the secondary label sits on the name of the function, because there is no return type to point at.
This is the one mistake that comes with a help line: ``this value is unused: bind it with `let name = …`,
or return it from the function``. The compiler does not offer an edit, because what to call the variable,
and whether the value is to be bound or returned, is for the author to say. The second half is left out
where returning the value would not help: at the end of an `if` that has no `else`.

## Corrected

```ki corrected
fn f() -> Int { 1 }
fn main() { }
```

## Erroneous example

```ki erroneous pending=T36
fn f(a: Int) {}
fn main() { f(true) }
```

An argument is checked against the type of its parameter. The label on the `true` says
``expected `Int`, found `Bool` ``, and the secondary label on the parameter says
`the parameter is declared here`.

## Corrected

```ki corrected
fn f(a: Int) {}
fn main() { f(1) }
```

## Erroneous example

```ki erroneous pending=T36
fn main() { let x = if true { 1 } else { false } }
```

Both branches of an `if` that is used as a value have the same type, and the `then` branch is the one
that decides it. The label on the `false` says ``expected `Int`, found `Bool` ``, and the secondary label
on the `1` says ``the other branch has type `Int` ``.

## Corrected

```ki corrected
fn main() { let x = if true { 1 } else { 2 } }
```

## Erroneous example

```ki erroneous pending=T36
fn main() { if 1 { } }
```

The condition of an `if` must be a `Bool`, and Ki does not take a number for a truth value. The label on
the `1` says ``expected `Bool`, found `Int` ``. There is no secondary label, because no other place
explains the expectation; the note says the rule: ``an `if` condition must be `Bool` ``.

## Corrected

```ki corrected
fn main() { if true { } }
```

## Erroneous example

```ki erroneous pending=T36
fn main() { let b = true && 1 }
```

Each operator wants operands of one type: `&&` and `||` want `Bool`, and `+ - * / %` and the
ordering comparisons `< <= > >=` want `Int`. The label on the `1` says ``expected `Bool`, found `Int` ``,
and the secondary label on the operator says `` `&&` expects `Bool` operands ``.

## Corrected

```ki corrected
fn main() { let b = true && false }
```
