# E0801: alias refers to itself

An alias stands for another type: `type Meters = Float` makes `Meters` another name for `Float`, and
the compiler replaces the alias by that type wherever it is written. An alias that stands for itself,
directly (`type A = A`) or through other aliases (`type A = B` and `type B = A`), has nothing to be
replaced by, so it is an error. A `type` with a body, a sum or a record, is not an alias and may
mention itself (`type Nat { Zero, Succ(n: Nat) }`): it is a type of its own, and the name only says
how to reach it.

The primary label is on the first alias of the cycle in the file and says
`this alias is part of a cycle`. A secondary label on each of the others, in the order the cycle goes
through them, says `` through `B`, defined here ``; a cycle of one alias has none. The note says that
an alias stands for another type, so it cannot stand for itself. There is one error for the cycle, and
none for the aliases that only lead into it, nor for what uses any of them: they have the error type
until the cycle is mended. Aliases that lead back to each other in more than one way are one cycle
and one error, however many ways there are round it (`type A = (A, B)` and `type B = (A, Int)`): the
labels are then on every alias of it, in the order the compiler met them, which is not one path. The compiler offers no help and no edit, because which of the aliases is
the one to change is for the author to say.

## Erroneous example

```ki erroneous
type A = B
type B = A
fn main() {}
```

`A` stands for `B` and `B` for `A`. The label on the first `A` says it is part of a cycle, and the
label on `B` says the cycle goes through it.

## Corrected

```ki corrected
type A = B
type B = Int
fn main() {}
```

## Erroneous example

```ki erroneous
type Meters = Meters
fn main() {}
```

An alias that is its own target is a cycle of one, and has no secondary label.

## Corrected

```ki corrected
type Meters = Float
fn main() {}
```
