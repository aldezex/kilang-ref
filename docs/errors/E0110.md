# E0110: unterminated string literal

A string literal is written between double quotes and ends on the line where it starts: a line
break inside a string is an error. The line ended, or the file did, before the closing `"` came.

The compiler points at the opening quote, which is where the string starts, and goes on reading at
the line break, so the lines after the string are checked as usual.

Strings cannot be used in expressions yet, so, for now, `ki check` reports E0201 for the string of the
corrected example below as a whole. The fence that says `also=E0201` is the sign of that: when the
compiler reads strings in expressions, those words and this paragraph go away.

## Erroneous example

```ki erroneous
fn main() {
  let s = "abc
}
```

The closing quote is missing from the second line. The compiler suggests closing the string and offers to write the quote at the end of the line. It cannot know where the string was meant to end, so that is what the help says: if the string should end earlier, as in `print("abc) }`, put the quote there instead.

## Corrected

```ki corrected also=E0201
fn main() {
  let s = "abc"
}
```

The string is closed on its line.
