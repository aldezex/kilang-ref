# E0204: expression is nested too deeply

Parentheses (of an expression, a tuple, or a tuple type), call arguments, the values of the fields of a
record literal, prefix operators, the parts of an `if` or of a `match` (its scrutinee, and the guard and
the body of each arm) and blocks may nest at most 256 levels deep inside one another. The parser reads each
level with a call of its own, and so does every later pass, so the limit protects the compiler from a file
made to exhaust its stack.

The compiler reports the first level past the limit, 257, and skips the rest of the statement. The title
says what is too deep, an expression or (`type is nested too deeply`) a tuple type, and the help says how
to split it: with `let` bindings for an expression, with `type` aliases for a tuple type.

A pattern has a count of its own, because it holds no expression: the arguments of a constructor, the
fields of a record pattern, the elements of a tuple or of a list and a pattern between parentheses may
nest 256 levels inside one pattern, however deep the expressions around the `match` are. Past that the
title is `pattern is nested too deeply`, and the help is to match the inner part with a second `match` in the
body of the arm, or, for a pattern in a `let`, which has no body, after the `let`. The compiler skips the arm, or
the `let`, that holds the pattern, and reads the arms after it. A hundred thousand alternatives of `|`, or elements of a tuple or of a list, are no depth: they are
siblings.

## Corrected

```ki corrected

  print(a)
}
```

## Corrected

```ki corrected
type T { S(T), Z }
fn f(x: T) -> Int {
  match x {
    S(y) => match y { _ => 1 }
    _ => 0
  }
}
fn main() {}
```
