# E0105: integer literal is too large

An `Int` is a signed 64-bit integer, so the largest `Int` is 9223372036854775807. A literal
with a larger value does not fit and is rejected, whatever its base (`0x8000_0000_0000_0000` is
too large as well).

The smallest `Int`, -9223372036854775808, cannot be written as a literal either: the minus sign
is an operator applied to the literal `9223372036854775808`, which is already too large. Write it
as `-9223372036854775807 - 1`. A pattern has no expression to write it with: to match the smallest
`Int` in an arm, bind the value and compare it in a guard, `x if x == -9223372036854775807 - 1`. The
lexer reports the literal before it is known to be in a pattern, so the help says both: what an
expression writes, and what the arm of a `match` does.

## Erroneous example

```ki erroneous
fn main() { print(9223372036854775808) }
```

The literal is one more than the largest `Int`. The compiler states the limit and how to write the smallest `Int`.

## Corrected

```ki corrected
fn main() { print(9223372036854775807) }
```

The largest `Int` is a valid literal.

## Corrected

```ki corrected
fn main() { print(-9223372036854775807 - 1) }
```

The smallest `Int` is written as an expression.

## Erroneous example

```ki erroneous
fn sign(n: Int) -> Int {
  match n {
    -9223372036854775808 => 0
    _ => 1
  }
}
fn main() {}
```

The same literal in the arm of a `match`: a pattern cannot be written as a subtraction, so the help ends with
the guard.

## Corrected

```ki corrected
fn sign(n: Int) -> Int {
  match n {
    x if x == -9223372036854775807 - 1 => 0
    _ => 1
  }
}
fn main() {}
```

The value is bound and compared in a guard.
