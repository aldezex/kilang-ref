# E0409: unknown field

A field is named after a `.` (`p.z`) or inside a record literal (`Point { z: 1.0 }`), and the record
that is meant does not declare a field with that name. A record has exactly the fields its `type`
declares, so the name is a misspelling, or the field belongs to another type.

The primary label is on the name of the field and says `unknown field`; a secondary label points at the
`type` declaration, `` `Point` is defined here``, when it is in the same file. There is no note. If a
field of the record is spelled almost like the name, the compiler asks whether it was meant and offers
the edit that writes it (in a literal, only among the fields the literal does not give already: the edit
would write one of them twice); otherwise there is no help at all. A field that is only a name, `Point { xx }`,
is also the variable that gives its value: if that variable exists, the edit writes the field and keeps the
variable, `x: xx`. If it does not, the name is wrong twice, and the program has this error and E0301 for the
same name. The edit that mends both, `Point { x }`, is the one of E0301, which alone knows the variables: it
has it when `x` is a variable and a field that the literal does not give already, and then this error keeps
its question and has no edit, so that no two edits compete for the same name. The expression that held the
mistake has a type that is already wrong, so the place that uses it adds no error of its own. A literal with an
unknown field does not also say that the field it was meant to give is missing (E0410): it is the same
mistake.

## Erroneous example

```ki erroneous
type Point { x: Float, y: Float }
fn main() {
  let p = Point { x: 1.0, y: 2.0 }
  printFloat(p.z)
}
```

`Point` has no `z`, and `x` is the closest field, so the help says ``did you mean `x`?`` and the edit
writes it over `z`.

## Corrected

```ki corrected
type Point { x: Float, y: Float }
fn main() {
  let p = Point { x: 1.0, y: 2.0 }
  printFloat(p.x)
}
```

## Erroneous example

```ki erroneous
type Point { x: Float, y: Float }
fn main() { let p = Point { x: 1.0, why: 2.0 } }
```

The same error for a literal. `why` is not close enough to `y` for the compiler to suggest it, so
there is a label on the name and no help.

## Corrected

```ki corrected
type Point { x: Float, y: Float }
fn main() { let p = Point { x: 1.0, y: 2.0 } }
```
