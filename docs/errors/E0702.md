# E0702: refutable pattern in `let`

A `let` binds a value to the names of a pattern, and has no other arm to turn to if the value does not fit.
So its pattern must match every value that the initializer can have: a name, `_`, a tuple of those, a
record, or a constructor of a type that has only that constructor. A pattern that some value does not
match is refutable, and what the `let` should do for that value is a question that only a `match` can
answer.

The primary label is on the pattern and shows a witness, the value that it does not match: the label of
a pattern that leaves out `None` says that `None` is not covered. The witnesses are the ones of a `match`
(E0701): up to three, and then `and more`. A note gives the rule, and the help says to use `match` to
handle the other cases. There is no edit, because what the other cases do is for you to say.

## Erroneous example

```ki erroneous
type Maybe { None, Some(Int) }
fn value(m: Maybe) -> Int {
  let Some(x) = m
  x
}
fn main() {}
```

`m` may be `None`, which `Some(x)` does not match.

## Corrected

```ki corrected
type Maybe { None, Some(Int) }
fn value(m: Maybe) -> Int {
  match m {
    Some(x) => x
    None => 0
  }
}
fn main() {}
```

## Erroneous example

```ki erroneous
fn first(t: (Int, Int)) -> Int {
  let (a, 0) = t
  a
}
fn main() {}
```

A literal is never all of its type, so `(a, 0)` leaves out the pairs whose second element is another
number. The witness is the smallest one: ``(_, 1)``.

## Corrected

```ki corrected
fn first(t: (Int, Int)) -> Int {
  let (a, _) = t
  a
}
fn main() {}
```
