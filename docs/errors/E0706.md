# E0706: a `Float` literal cannot be a pattern

A pattern says which values an arm matches, and a `Float` has no value that a pattern can name. Matching
a pattern compares with `==`, and `==` on floats is not an equivalence: `NaN != NaN`, so a `NaN` would
never match even the arm that was written for it, and `0.0 == -0.0`, so two values that print differently
would take the same arm. Ki does not let a `match` or a `let` hide that, so a float written where a
pattern goes is an error, in any place a pattern may be: an arm, a `let`, and inside a constructor, a
tuple, a list, a record pattern or an alternative of `|`. A negative literal is the same, `-1.5`.

The primary label is on the literal, with its sign if it has one, `not a pattern`. The note gives the
reason above. The help is to bind the value to a name and compare it in a guard, with the literal written
as the program has it: `x if x == 1.5`. The name is one that the file does not spell anywhere, `x`, or `x1`,
`x2`… if the file has an `x` (a parameter, a variable of the arm, a field), so that the variable of the help
hides nothing that the arm uses. An arm that has a guard already says to join the comparison to it
(`x if x == 1.5 && …`), and a chain of alternatives, `1 | 2.5`, that the guard compares each of them
(`x if x == 2.5 || x == …`). A `let` has no guard, so its help says to take the value apart with a `match`.
There is no edit, because the name of the variable is not something the compiler can choose. The arm is
read to its end all the same, so a mistake after the literal is reported too, unless it is fewer than three
tokens after this one: the parser takes it for the same mistake seen again, so `(1.5, 2.5)` says it once and
`P { x: 1.5, y: 2.5 }` twice. A float that the lexer rejected (`1e999`) is that error alone, E0109, and no
E0706 comes with it.

## Erroneous example

```ki erroneous
fn f(x: Float) -> Int { match x { 1.5 => 1
  _ => 0 } }
fn main() {}
```

`1.5` is a `Float`, so it cannot start an arm. The label is on the literal.

## Corrected

```ki corrected
fn f(x: Float) -> Int { match x { y if y == 1.5 => 1
  _ => 0 } }
fn main() {}
```

The pattern `y` matches any float and the guard decides, by `==`, which of them take this arm. A guard
does not count for the exhaustiveness of the `match`, so the arm for `_` stays.

## Erroneous example

```ki erroneous
fn f(p: (Float, Float)) -> Int { match p { (0.0, y) => 1
  _ => 0 } }
fn main() {}
```

The float is inside a tuple pattern: it is just as much a pattern, and the label is on the `0.0` alone.

## Corrected

```ki corrected
fn f(p: (Float, Float)) -> Int { match p { (x, y) if x == 0.0 => 1
  _ => 0 } }
fn main() {}
```

## Erroneous example

```ki erroneous
fn f(t: (Int, Float)) -> Int { let (a, 0.5) = t
  0 }
fn main() {}
```

A `let` is no place for a float either, and it has no guard to compare in: the help says to use a `match`.

## Corrected

```ki corrected
fn f(t: (Int, Float)) -> Int { match t { (a, x) if x == 0.5 => a
  _ => 0 } }
fn main() {}
```

The `match` binds the float to `x` and the guard compares it; the arm for `_` takes the rest.
