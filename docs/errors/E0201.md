# E0201: expected <what>, found <token>

The parser needed a certain piece of syntax and found something else. The message says what was
needed (an expression, an identifier, a type, an item, a newline, or a punctuation mark such as `)`)
and what was found, quoted as it is written in the file.

When the missing piece is a closing `)` or `]`, the compiler also points at the opening delimiter
that is still open. If what it found instead is a `}`, a `]`, a `;`, a `let` or the start of an
item, the closer is what is missing: the compiler suggests closing the delimiter and offers to
write the closer. If it found a name, a number or any other token that could go on inside the
delimiters, a `,` or an operator may be missing instead, and it offers no edit. When a `let` has no
name, the help shows what a `let` looks like. In the other cases there is no single obvious edit, so
there is none to suggest.

## Erroneous example

```ki erroneous
fn main() { print(1 }
```

The `}` was found where the `)` of the call should be. The compiler points at the `(` that is still open, suggests closing it and offers to write the `)` right after the `1`, where the expression stopped.

## Corrected

```ki corrected
fn main() { print(1) }
```

## Erroneous example

```ki erroneous
fn main() { let = 1 }
```

A `let` binds a name, and the name is missing. The compiler shows the shape of a `let`; it cannot guess the name.

## Corrected

```ki corrected
fn main() { let x = 1 }
```

## Erroneous example

```ki erroneous
fn main() { let sum = 1 + }
```

The `+` needs an expression on its right and found the `}`. The label says what was expected at that place.

## Corrected

```ki corrected
fn main() { let sum = 1 + 2 }
```
