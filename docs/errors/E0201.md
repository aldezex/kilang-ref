# E0201: expected <what>, found <token>

The parser needed a certain piece of syntax and found something else. The message says what was
needed (an expression, an identifier, a type, an item, a newline, a field name or tuple index after a `.`, or a
punctuation mark such as `)`)
and what was found, quoted as it is written in the file.

When the missing piece is a closing `)` or `]`, the compiler also points at the opening delimiter
that is still open. If what it found instead is a `}`, a `]`, a `;`, a `let` or the start of an
item, the closer is what is missing: the compiler suggests closing the delimiter and offers to
write the closer. If it found a name, a number or any other token that could go on inside the
delimiters, a `,` or an operator may be missing instead, and it offers no edit. When a `let` has no
name, the help shows what a `let` looks like. When a name in the body of a `type` has no `:` after it,
the help says that a field is written `name: Type` and a variant starts with an uppercase letter, because
the name may have been meant as either; the same help is on the `:` that follows a variant
(`type P { X: Float }`), a field written with a capital. A type name in small letters has the help that a
type name starts with an uppercase letter and the edit that writes it so, and a field name with a capital
in a record literal has the help that it starts with a lowercase letter and the edit that writes it so.
When the `,` between two fields of a record literal is missing, or a `;` stands where it goes, the help is
to separate the fields with `,`, and the edit writes it; the literal is read to its `}` all the same. The next
field may be only a name, `Point { x` and then `y` on the line below: that is a field too when it is on the
line of the one before or straight under it. A name alone anywhere else on its own line is not taken for a
field, since it may be a statement after a literal whose `}` is missing, and then the error is about the `{`.
After a `.`, an index written with leading zeros (`t.01`) has the edit that writes it without them. A
number that the lexer has already rejected (`t.1_`, `t.1e999`) is that error alone, E0105, E0107 or
E0109, and no E0201 comes with it. In the other cases there is no single obvious edit, so there is none
to suggest.

## Erroneous example

```ki erroneous
fn main() { print(1 }
```

The `}` was found where the `)` of the call should be. The compiler points at the `(` that is still open, suggests closing it and offers to write the `)` right after the `1`, where the expression stopped.

## Corrected

```ki corrected
fn main() { print(1) }
```

## Erroneous example

```ki erroneous
fn main() { let = 1 }
```

A `let` binds a name, and the name is missing. The compiler shows the shape of a `let`; it cannot guess the name.

## Corrected

```ki corrected
fn main() { let x = 1 }
```

## Erroneous example

```ki erroneous
fn main() { let sum = 1 + }
```

The `+` needs an expression on its right and found the `}`. The label says what was expected at that place.

## Corrected

```ki corrected
fn main() { let sum = 1 + 2 }
```

## Erroneous example

```ki erroneous
type Point { x: Int }
fn main() { if Point { x: 1 }.x == 1 { print(1) } }
```

In the head of an `if`, a name and a `{` start the block, so a record literal there has to be between
parentheses. What the parser found is a whole literal and not one token, so this message is its own:
the compiler reads the literal as it is written, reports it once, and offers to write the `(` and the
`)`.

## Corrected

```ki corrected
type Point { x: Int }
fn main() { if (Point { x: 1 }).x == 1 { print(1) } }
```

## Erroneous example

```ki erroneous
type Point { x: Float, y: Float }
fn main() {
  let p = Point {
    x: 1.0
    y: 2.0
  }
}
```

Between two fields of a record literal there is a `,`: the layout of a `type` body, with one field on each
line and nothing after it, is not the one of a literal. The compiler found the `y` where a `,` or the `}`
was expected, and offers to write the `,` after the `1.0`, where the first field ends; the `{` is closed,
and it does not say it is not.

## Corrected

```ki corrected
type Point { x: Float, y: Float }
fn main() {
  let p = Point {
    x: 1.0,
    y: 2.0
  }
}
```
