# E0410: missing field

A record literal gives a value to every field of the record, or it ends with `..base` to take the
fields it leaves out from another value of the same type. A literal that does neither has no value for
some field, and Ki does not make one up.

The primary label is on the closing brace of the literal, `` `y` is not given``, and there is a secondary
label on the declaration of each missing field, `declared here`, when it is in the same file. The note
says `a record literal names every field, or ends with `..base``. There is no help and no edit: which
value `y` should have cannot be worked out from the program. When several fields are missing the
compiler reports one error that lists them, ``fields `y` and `z` are not given``, and not one for each; a
record with very many fields lists the first eight and says how many more there are. A literal that also
has an unknown field (E0409) does not report this error: the unknown field is most likely the one that
was missing, misspelled.

A record pattern is the same: it names every field of the record or ends with `..`, which skips the
fields it does not name (`Point { x, .. }`). A pattern that does neither has no pattern for some field.
The message says ``missing field `y` in pattern `Point { … }` ``, the primary label is on the closing
brace, and the secondary labels and the note are the literal's, worded for a pattern: `a record pattern
names every field, or ends with `..``. Here there is a help, ``add `..` to skip the rest``, because the
fix is certain whichever fields are missing: when the pattern is on one line the compiler offers the edit
that writes it, after the last field with its comma (`Point { x }` becomes `Point { x, .. }`), or, if a
comma follows the last field already or no field is named, just before the brace. A pattern with an
unknown field (E0409) does not also say that a field is missing: the unknown one is most likely it.

## Erroneous example

```ki erroneous
type Point { x: Float, y: Float }
fn main() { let p = Point { x: 1.0 } }
```

`y` has no value. The label is on the `}`, where the list of fields ends.

## Corrected

```ki corrected
type Point { x: Float, y: Float }
fn main() { let p = Point { x: 1.0, y: 2.0 } }
```

## Erroneous example

```ki erroneous
type Point { x: Float, y: Float, z: Float }
fn main() { let p = Point { x: 1.0 } }
```

Two fields are missing: one error lists both, with a secondary label on each declaration.

## Corrected

```ki corrected
type Point { x: Float, y: Float, z: Float }
fn main() {
  let o = Point { x: 0.0, y: 0.0, z: 0.0 }
  let p = Point { x: 1.0, ..o }
}
```

## Erroneous example

```ki erroneous
type Point { x: Float, y: Float }
fn main() {
  let p = Point { x: 1.0, y: 2.0 }
  let Point { x } = p
}
```

The pattern of a `let` names `x` and not `y`. The label is on the `}` and the help says ``add `..` to skip
the rest``; the edit writes `, ..` after the `x`.

## Corrected

```ki corrected
type Point { x: Float, y: Float }
fn main() {
  let p = Point { x: 1.0, y: 2.0 }
  let Point { x, .. } = p
}
```
