# E0704: pattern binds a name twice

A pattern names the parts of a value, and each name stands for one of them. Writing the same name twice,
`(x, x)`, does not say that the two parts are equal: it would only leave unsaid which of them `x` is in
the body. A pattern cannot compare two parts, so it binds each name once.

The primary label is on the second use of the name, `bound again here`, and the secondary label on the
first, `first bound here`. A note says the way out: to compare two parts, bind them apart and use a
guard. There is no help and no edit, because what the second one should be called is for the author to
say. In the body the name stands for the first; the second is a variable that no name stands for. A name
that is bound in two alternatives of an or-pattern is not a repeat, because every alternative binds the
same names (E0703); one that is bound before the or-pattern and again inside it is.

## Erroneous example

```ki erroneous
fn same(p: (Int, Int)) -> Bool {
  match p {
    (x, x) => true
    _ => false
  }
}
fn main() {}
```

`x` names both elements of the tuple. The label is on the second `x`.

## Corrected

```ki corrected
fn same(p: (Int, Int)) -> Bool {
  match p {
    (x, y) if x == y => true
    _ => false
  }
}
fn main() {}
```

## Erroneous example

```ki erroneous
type Point { x: Int, y: Int }
fn diagonal(p: Point) -> Bool {
  match p {
    Point { x: a, y: a } => true
    _ => false
  }
}
fn main() {}
```

The same mistake in a record pattern, with each field given its own pattern. A pun, `Point { x, y: x }`,
binds the name of the field, so it is the same error.

## Corrected

```ki corrected
type Point { x: Int, y: Int }
fn diagonal(p: Point) -> Bool {
  match p {
    Point { x: a, y: b } if a == b => true
    _ => false
  }
}
fn main() {}
```
